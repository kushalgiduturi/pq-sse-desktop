# Web plan: download site, web installer, release pipeline

Goal: a stranger on a Windows PC opens the site, understands PQ-SSE Desktop in one screen,
downloads a small web installer, which fetches and verifies the right package, installs it and
starts the app. Every step says honestly what is verified and what Windows may warn about.

## 0. What "web installer" means here

A small Windows program (`PQ-SSE-Web-Setup.exe`) that downloads the full package, checks it and
runs it. It is **not** a version of the app that runs in the browser: the app needs local
Python, keeps keys on the user's own PC and may use the GPU. Nothing here builds a browser app.

## 1. Found while reading (needs your decision)

**The published GPU installer contains files NVIDIA does not list as redistributable.**
The GPU build copies NVIDIA's CUDA 12.0 runtime and NVRTC (allowed) and also **888 CUDA header
files** from NVIDIA's pip wheels into `cuda_runtime\include`. The CUDA 12.0 EULA (Attachment A,
read at docs.nvidia.com/cuda/archive/12.0.1/eula) lists as redistributable on Windows:
`cudart.dll` (and versioned variants such as `cudart64_12.dll`), `nvrtc.dll` and
`nvrtc-builtins.dll` (and variants such as `nvrtc64_120_0.dll`), and only four headers:
`nvrtc.h`, `cuda_fp16.h` and `cuda_fp16.hpp`, `cuda_occupancy.h`, `cufile.h`. Headers such as
`cuda_runtime.h` or `vector_types.h` are not listed. That installer is attached to the public
`v0.1.0` Release created earlier today.

Proposal (decision W1):
1. Now, with your yes: remove `PQ-SSE-Desktop-Setup-0.1.0-GPU.exe` from the v0.1.0 Release
   (`gh release delete-asset v0.1.0 PQ-SSE-Desktop-Setup-0.1.0-GPU.exe -R kushalgiduturi/pq-sse-desktop`)
   and edit the notes to say the GPU build is not available yet. The Standard installer has
   no NVIDIA files and stays.
2. In milestone 1: find the smallest header set the app's kernels really need, by building the
   GPU variant with only the four allowed headers and running `--gpu-selftest`. If that passes,
   ship only those. If CuPy needs more headers, the GPU package becomes a separate "GPU pack"
   that the user's own PC fetches from NVIDIA's official pip packages (the user installs NVIDIA's
   files from NVIDIA, under NVIDIA's terms), and the installer ships only Attachment A files.
3. `scripts/build_helpers.py cuda-runtime` copies only an allowlist of files and fails on
   anything else; a test checks the list against Attachment A.

## 4. Web installer: technology

**Recommended: Inno Setup 6.7 stub (`installer/web-setup.iss`).**

- Gives for free: the same wizard look and welcome text as the full installer, per-user without
  admin rights, the system proxy (Windows HTTP stack), a download page with progress and size,
  SHA-256 checking, and in 6.7 signature checking with `.issig` files against a public key built
  into the stub. Expected size about 2 to 3 MB. Built by `ISCC` in the release script.
- GPU detection in Pascal Script through WMI (`Win32_VideoController`: name and `DriverVersion`),
  which needs no extra tools. NVIDIA's Windows driver version `31.0.15.2833` maps to `528.33`
  (last five digits). Any failure means Standard. The user can always override.
- Runs the full installer with `/SILENT` or `/VERYSILENT` passed through, `/DIR=` passed through,
  offers to launch at the end, deletes its temporary files, logs to
  `%LOCALAPPDATA%\PQ-SSE-Desktop\logs\web-setup.log`.
- Gaps, stated honestly: Inno's downloader follows HTTP redirects itself, so the stub cannot
  refuse a redirect to a host outside the allowlist **before** it happens. It checks the final
  URL's host after the download and refuses to run anything from elsewhere, and the signature
  check makes a swapped file fail regardless of where it came from. It does not resume a broken
  download from the middle: it retries from the start (the Standard package is 54 MB). I will
  verify both behaviors in tests and change this text if Inno does better.

**Alternative: a small Go stub** (Go 1.26 is on this PC; Rust is not). Full control: refuse any
redirect off the allowlist before following it, resume with HTTP range requests, Ed25519. Costs:
a Windows GUI has to be written by hand (Win32 calls) or the stub becomes a console window, the
system proxy needs extra code (Go does not read the Windows proxy setting by itself), a second
toolchain to maintain, and about 5 to 8 MB. My judgment: not clearly better, because the
signature check covers the redirect risk and the package is small enough to retry. I will build
the Inno stub unless you choose Go.

GitHub release downloads always redirect from `github.com` to a separate file host
(`release-assets.githubusercontent.com`, older `objects.githubusercontent.com`). The allowlist
is therefore: `kushalgiduturi.github.io`, `github.com`, `release-assets.githubusercontent.com`,
`objects.githubusercontent.com`.

## 5. Trust model (for DISTRIBUTION.md and the Security page)

- A SHA-256 hash checked against a manifest catches a damaged or swapped file. If an attacker
  controls both the manifest and the file, the hash proves nothing.
- The signed manifest (W3) closes that gap as long as the private key stays private. If the key
  is stolen, it proves nothing either. Key custody is on you.
- Second sources: the hashes are also in the Release notes and in `SHA256SUMS.txt`; the site and
  the files live on different hosts (Pages and Releases), though both are GitHub.
- None of this is Authenticode code signing: Windows still shows "Unknown publisher" and
  SmartScreen. The site says exactly that.
- Code signing options, researched, nothing bought or applied for:
  - Azure Artifact Signing (formerly Trusted Signing): about 9.99 US dollars a month (Basic).
    Microsoft Q&A answers in 2026 say individual developers are accepted only in the USA and
    Canada, organizations in the USA, Canada, EU and UK. **Not verified** on an official
    eligibility page; your country decides.
  - Commercial OV or EV certificate: a few hundred dollars a year; EV no longer removes the
    SmartScreen warning at once (Microsoft documentation). Prices not verified with sellers.
  - SignPath Foundation: free for OSI-licensed open-source projects with public source (MIT and
    the public repo qualify on paper); the certificate names SignPath Foundation as publisher,
    and releases must carry their attribution line. **Not verified**: whether a project of this
    size and age is accepted, and their current review process.
- Signing hooks stay in `build_release.ps1`, off by default, secrets from the environment only.
  A hook for the web stub is added the same way.

## 7. Risks

- NVIDIA headers (section 1): the GPU variant may have to become a separate pack, or be marked
  "not available yet" for a while.
- Inno's downloader behavior on redirects and resume (section 4) is documented thinly; tests
  decide what the docs say.
- SmartScreen and antivirus: a new unsigned stub that downloads and runs another program is
  exactly what heuristics flag. Expect warnings until the files are signed; the site says so.
- GitHub Pages and Releases are one company: the "different hosts" mitigation is weak; the
  signature (W3) is the real protection.
- Screenshots: the restyle is finished, so the site uses real restyled screenshots, no
  placeholders.
- `actionlint` and the axe-core copy are new tools; both are optional and stated if missing.
- Already public: the repo, the v0.1.0 Release with two installers, and your Gmail address in the
  commit history (your choice). The brief's "ask before anything public" applies from here on.
