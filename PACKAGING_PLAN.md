# Packaging plan

Goal: a person with no Python can install and run PQ-SSE Desktop on Windows 10 or 11.
Outputs: a portable folder and zip, a per-user installer, one build command, and checks
that run the built program. No protocol or cryptography change.

## 1. What gets built

```
%LOCALAPPDATA%\PQ-SSE-Desktop-build\            everything, outside OneDrive
  venv\                                         build virtual environment (pinned versions)
  standard\dist\PQ-SSE-Desktop\                 one-folder app, CPU only
  gpu\dist\PQ-SSE-Desktop\                      one-folder app with CuPy and the NVRTC runtime (-WithGpu)
  release\<version>\
    PQ-SSE-Desktop-Setup-<version>.exe          installer, Standard
    PQ-SSE-Desktop-Setup-<version>-GPU.exe      installer, GPU (-WithGpu)
    PQ-SSE-Desktop-<version>-portable-standard.zip
    PQ-SSE-Desktop-<version>-portable-gpu.zip   (-WithGpu)
    SHA256SUMS.txt
```

## 3. Milestones

1. Portable exe: resources, version, icon, About, logging, job object, `--smoke-test`, build script runs it.
2. GPU variant: bundled NVRTC, `--gpu-selftest`, tested without the CUDA Toolkit on PATH, sizes reported.
3. Installer (Inno Setup), portable zip, checksums.
4. `build_release.ps1`, lock files, `scripts/test_installer.ps1`, CI workflow.
5. Docs: INSTALL, DISTRIBUTION (SmartScreen, signing, antivirus), RELEASE_NOTES, README.

Each milestone: tests, commit.

## 4. Decisions

- **P1 Version.** `pyproject.toml` is the only place. The build bundles a copy of it; the app
  reads it with `tomllib`; the build script and the installer get it from `build_helpers.py version`.
- **P2 One-folder build, windowed.** As asked. A windowed program has no console, so
  `--smoke-test` and `--gpu-selftest` take `--report <file>` and also write to standard
  output when it is redirected. The scripts use the report file and the exit code.
- **P3 Smoke test uses real parts, throwaway data.** It starts the real cloud child process
  on a free port and runs Setup, Join, BuildIndex, Publish, TokenGen, Search, Verify,
  Decrypt, update, Revoke with the default parameter set (ML-KEM-768, ML-DSA-65). Data goes
  to a temporary folder that is deleted afterwards, never to the user's data folder. It
  also checks that the cloud does not answer on a non-loopback address, that a revoked
  doctor is refused, and (frozen) that the install folder was not written to.
- **P4 Two setup files, not one with a choice.** One Inno script, compiled once per variant.
  Reason: the GPU payload is several hundred MB, so a combined installer would make every
  user download it. Both use the same AppId, so installing one over the other replaces it.
- **P5 Closing the app on upgrade and uninstall.** `CloseApplications` and
  `RestartApplications` are set, but Restart Manager cannot close the windowless cloud child
  politely. So the installer first runs `stop_app.ps1`: it asks the main window to close
  (which stops the cloud cleanly), waits, then ends whatever is left from that install
  folder only. In addition the app now puts the cloud child in a Windows job object, so it
  ends whenever the app ends, even after a crash.
- **P6 Uninstall keeps user data by default.** Interactive uninstall asks, default No.
  Silent uninstall never deletes `%LOCALAPPDATA%\PQ-SSE-Desktop`.
- **P7 GPU runtime.** Bundle only the NVRTC compiler DLLs (and the CUDA runtime DLL if CuPy
  needs it) from NVIDIA's pip wheels, not the full `[ctk]` set (cuBLAS and friends are
  hundreds of MB and unused here). At start the frozen app adds the bundled folder to the
  DLL search path. The only outside requirement is the NVIDIA driver. If the driver is
  missing or the self-test fails, the existing CPU fallback applies and says why.
  The CuPy kernel cache is moved to `%LOCALAPPDATA%\PQ-SSE-Desktop\cupy_cache`.
  What testing showed (all handled now):
  - CuPy 14 also needs the CUDA header files, not only the compiler DLL. The app ships a
    minimal CUDA folder `_internal\cuda_runtime` (`bin` with 3 DLLs, `include` with the
    headers, 50 MB) and sets `CUDA_PATH` to it for its own process only.
  - PyInstaller silently copied cuBLAS, cuFFT and other libraries from the CUDA Toolkit
    installed on the build PC: 1,648 MB instead of 407 MB. The build script now hides the
    Toolkit (PATH, CUDA_PATH) while packaging and fails if such a library is in the output.
  - A standard-library module (`graphlib`) that CuPy imports from compiled code had to be
    listed by hand.
  - The bundled compiler is the CUDA 12.0 Update 1 release (oldest 12.x, so it asks least
    of the driver). NVIDIA's release notes state Windows driver 528.33 or newer for it. The
    "525.60" in the task text is the Linux number. Tested only with driver 610.62.
- **P8 License: MIT** (none existed; you can change it). Copyright line says
  "PQ-SSE Desktop authors"; put your name there if you prefer. Third-party license texts are
  collected from the build environment into `THIRD-PARTY-LICENSES.txt`. Long dashes inside
  those third-party texts are replaced by hyphens to keep rule 1, and the file says so.
- **P9 Lock files** hold the versions of the working environment. The GPU extras are in
  their own file so the Standard build never installs them.
- **P10 Inno Setup was not installed on this PC.** Installed per user, without admin (done,
  version 6.7.3, in `%LOCALAPPDATA%\Programs\Inno Setup 6`):
  `winget install -e --id JRSoftware.InnoSetup --source winget --override "/VERYSILENT /CURRENTUSER /NORESTART"`.
  The build script looks for `ISCC.exe` on PATH, under `%LOCALAPPDATA%\Programs\Inno Setup 6`
  and under Program Files, and stops with that install command otherwise.
- **P11 Signing is off.** `-SignCert <pfx>` with the password from the environment variable
  `PQSSE_SIGN_PASSWORD` signs the exe and the setup files with `signtool`. Not tested here:
  there is no certificate.
- **P12 Upgrade test.** The release build compiles a second, throwaway installer from the same
  payload with version 0.0.1, installs it, starts the app, installs the real version over
  it, and checks the result. The throwaway installer is not shipped.
- **P13 Firewall.** The cloud binds to 127.0.0.1 only (asserted in a test and in the smoke
  test). Windows shows no firewall prompt for loopback-only listeners. The installer test
  also checks that no firewall rule for the exe exists afterwards.

- **P14 Build environment uses the two PySide6 parts** (Essentials and Addons) instead of
  the umbrella package, so WebEngine and Pdf are not even installed there.
- **P15 The portable test simulates a non-ASCII user name** by pointing LOCALAPPDATA,
  APPDATA, USERPROFILE, TEMP and TMP at a folder with accented and Japanese characters. A
  real Windows account with such a name was not created.
- **P16 The builds in this work session ran inside the Claude desktop app**, which redirects
  everything written under `%LOCALAPPDATA%` to a private folder
  (`%LOCALAPPDATA%\Packages\Claude_...\LocalCache\Local`). The scripts are unchanged by
  this; run from a normal PowerShell they use the real `%LOCALAPPDATA%`. The release was
  copied to a normal folder with `-CopyTo`. The installer test therefore ran against the
  redirected Start Menu and registry view; run `scripts\test_installer.ps1` once from a
  normal PowerShell to repeat it against the real ones.
- **P17 The interactive "delete my data too?" question of the uninstaller** cannot be
  answered by a script without risking the real data folder, so only the silent path (data
  always kept) is tested automatically.

## 5. Risks

- CuPy may need more NVIDIA DLLs than NVRTC. Found by testing with the Toolkit removed from PATH.
- Antivirus or SmartScreen on other PCs: cannot be tested here, documented honestly.
- A clean PC without Python, a PC without an NVIDIA GPU, Windows 10: not available here,
  listed under "Not verified" in the release notes.
